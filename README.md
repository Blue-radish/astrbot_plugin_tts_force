# 说一声就念给你听 `astrbot_plugin_tts_force`

模型的回复**该不该变成语音**，由三条路决定，优先级从高到低：

| 顺序 | 触发条件 | 结果 |
|---|---|---|
| 1 | 用户消息里带 `force_keywords`（“发语音”“念给我听”…） | 一定语音 |
| 2 | 模型在回复最前面写 `voice_markers`（默认 `<语音>`） | 语音，标记本身删掉不念 |
| 3 | 普通短回复按 `random_rate` 掷骰子 | 命中才语音 |

插件会把「什么时候该用语音」注入系统提示词（`inject_prompt` 可关，`prompt_hint` 可整段自定义），
让模型按**内容**判断，而不是纯随机——安慰、撒娇、道晚安、一句情绪很重的话适合念；
讲原理、列清单、带代码链接、超长回复不适合。

## 随机不是纯掷骰子

命中概率之前先过五道闸，任何一道不过就发文字：

1. `max_chars` 字数上限（默认 50 字，0 = 不限制）
2. 清洗后至少 6 个字（只剩符号或动作描写的不念）
3. 不带链接、代码块、清单/步骤、大段英文数字（念出来是噪音）
4. 距上次**随机**语音至少 `random_min_gap` 秒（默认 600）
5. 群聊必须在 `random_groups` 白名单里；私聊永远允许

模型标记和用户点名不受 4、5 限制——那是明确意图，不该被随机规则挡住。

每次决定都写日志：发语音时标注来源（`用户要求` / `模型标记` / `随机`），
没发时写明原因（`这次没掷中（15%）` / `带链接，念出来是噪音` / `群 xxx 不在随机白名单里`）。

## 合成前清洗

括号里的动作神态 `（她低下头）`、`【】` 注释、markdown 符号、代码块都不会被念。
合成失败、超时、冷却中、上一条还在合成——一律保留原来的文字回复，不会变成没人说话。

## 配置

| 键 | 默认 | 说明 |
|---|---|---|
| `enable` | `true` | 总开关 |
| `provider_id` | `qwen3-tts` | TTS provider id；拿不到就退回当前会话默认 TTS |
| `voice_markers` | `<语音>` 等 7 种 | 模型表示「这条用语音」的标记，出现即删 |
| `force_keywords` | `发语音` 等 6 种 | 用户点名强制语音（兜底） |
| `strip_patterns` | 6 条正则 | 合成前删掉的内容 |
| `strip_markdown` | `true` | 顺带去掉 `# * _ \` > \|` 与代码块 |
| `max_chars` | `50` | 要念的字数上限，超过发文字（0 = 不限） |
| `cooldown` | `0` | 两次语音之间的最小间隔（秒） |
| `timeout` | `300` | 单次合成超时（秒） |
| `random_rate` | `15` | 日常闲聊改用语音的概率（0-100，0 = 关闭随机） |
| `random_min_gap` | `600` | 两次随机语音之间的最小间隔（秒） |
| `random_groups` | `[]` | 允许随机语音的群号，留空 = 只在私聊随机 |
| `inject_prompt` | `true` | 是否往系统提示词注入语音规则 |
| `prompt_hint` | `""` | 自定义提示词，支持 `{marker}` `{max_chars}` 占位 |
