# 说一句就念给你听 · astrbot_plugin_tts_force

把「这句话用语音说」交给模型，插件只负责**可靠地发出去**。

插件只提供一个工具：

```
send_voice(text)   →   合成音频，作为独立一条消息发给用户
```

模型可以先用文字说一句，再调用它补一段语音；可以判断这次该念还是该写。插件不猜、不掷骰子、不改写回复。

> **和 AstrBot 自带 TTS 的关系**
> 请把 AstrBot 自带的 TTS 关掉（`provider_tts_settings.enable = false`），否则宿主会先念一遍，变成两遍。
> 语音由 AstrBot 的 TTS 提供商合成，本插件负责「念什么、念得成不成」。

## 安装

1. 把本目录放进 AstrBot 的 `data/plugins/astrbot_plugin_tts_force/`
2. 在「提供商」页配好一个 TTS 提供商（`text_to_speech` 类型）
3. 关掉 AstrBot 自带的 TTS
4. 重启 AstrBot，插件配置里「语音提供商」留空＝跟随当前会话，或指定一个
5. 私聊机器人发 `/语音测试`，确认能真的收到一条语音

## 模型看到什么

工具说明里只有四条，这就是全部的「策略」：

- 适合发语音：口语化、简短的句子——闲聊、问候、情绪表达、道谢道歉、哄人
- 适合文字：技术长文、代码、命令、路径、链接、需要复制回看的内容
- 用户要求时（「念给我听」「用语音说」「语音回我」）一定调用；先用文字说一句再调用也可以
- 太长会被拒绝，按返回的长度提示缩短后再调用，不要分段连发

没有「一次只能一句」「数字一律用文字」这类硬规则——「早上七点叫你」也是自然的语音。
字数上限由代码强制执行。

## 工具返回什么

| 情况 | 返回给模型 | 用户收到 |
|---|---|---|
| 成功 | 「语音已经发出去了，别再把同一句用文字重复」 | 一条语音消息 |
| 超过字数上限 | 「这段 63 字，超过上限 50 字，请缩短再调」 | 什么都没有（不截断句子） |
| 上一条还在合成 | 「还在合成，稍等或先用文字」 | 什么都没有 |
| 提供商/网络/鉴权问题 | 分类 + 脱敏后的具体原因 | 什么都没有 |
| 音频文件不可用 | 「合成结果不可用：音频数据被截断」 | 什么都没有 |
| **指定的提供商不存在** | 「配置的语音提供商 X 不存在，请到设置里重新选择」 | 什么都没有（不会偷偷换别的服务发） |
| 发送失败 | 「语音没有发出去：原因」 | 什么都没有 |
| 发送超时 | 「发送结果**未确认**，可能已经发出去了，不要重复调用」 | 可能收到了，可能没有 |

失败都会变成一句能让模型继续决策的话，不会抛到模型框架里去（宿主取消工具调用那种情况除外）。
失败时的文字回复由模型自己写——因为只有它知道原本想说什么。

## 设置

| 键 | 默认 | 说明 |
|---|---|---|
| `provider_id` | `""` | 留空＝跟随当前会话；选了就只用它，失效直接报错，不会偷偷换成别的服务 |
| `max_chars` | `50` | 单次字数上限（10–300），超过就拒绝并回给模型实际长度。句子不会被截断 |
| `timeout` | `300` | 单次合成等待上限（5–600 秒） |
| `test_text` | 「语音测试成功…」 | `/语音测试` 念的那句话，最多 200 字 |

**插件没有自己的开关**：在插件管理页停用插件，宿主会同时停用它的工具，没必要多一个「插件开着但工具拒绝工作」的状态。

**关于 300 秒**：AstrBot 的工具调用默认只有 **120 秒**预算（`agent_runner.config.misc.tool_call_timeout`）。
设得比它大时，实际生效的是宿主的 120 秒，插件自己的超时提示不会出现。想让长语音真的跑完，
把宿主那个值也调大；否则就按 120 秒预算调字数。

字数为什么是 50：自建 qwen3-tts 实测约 **0.5 秒/字**，50 字≈25–30 秒合成。

## `/语音测试`

绕开模型直接合成一句固定话发给你，用来**隔离故障**：

- 收到了语音 → 提供商和插件都正常，问题在模型没有调用工具（去调工具说明或换模型）
- 报「鉴权失败/连不上/超时/收到文件但用不了」 → 是 TTS 服务或配置的问题

私聊谁都能用，群里只给管理员，受「同一会话不并发合成」约束。

## 并发与可靠性

- 同一会话同一时间只合成一条：会话位在第一个 `await` **之前**占住，工具和 `/语音测试` **共用同一条执行流程**，
  所以两者并发也只合成一次
- 合成结果要过校验：文件存在、非空；扩展名是 wav 就按 RIFF 块走一遍，确认 data 块真的带着它声称的字节数
  （只看头部声明会放过被截断的文件）
- 超时只罩在合成外面：发送阶段的超时单独报告「结果未确认」，不会被说成「合成超时」而让模型误以为没发出
- 错误信息先脱敏再截断（`Authorization: Bearer xxx` → `Authorization=***`、`api_key=abc+def/ghi==` → `api_key=***`），
  因为工具结果会回到模型上下文
- 耗时用 `time.monotonic()`；每次合成写日志：字数、提供商、耗时、失败原因

## 从 2.x 升级

3.0 删掉了随机概率、语音标记、关键词识别、场景正则、长期偏好记忆和自动改写回复；
3.1 又删掉了插件自带的 `enable` 开关（宿主停用插件即可）、手写的旧键清理（宿主加载配置时就会删掉
schema 之外的键）、以及「指定提供商不存在时回退到会话默认」的行为（现在直接报错）。

配置文件里最终只剩 `provider_id`、`max_chars`、`timeout`、`test_text` 四项。
如果你之前靠「概率自动发语音」，升级后不再有主动语音，只有模型显式调用工具才会念——这是设计意图。
