# 说一句就念给你听 · astrbot_plugin_tts_force

为 AstrBot 提供 `send_voice(text)` 工具，让模型根据人设、上下文和用户要求，选择用语音表达简短内容。

模型调用后，插件把文本合成音频，并作为一条独立消息发送到当前私聊或群聊。
成功时用户只收到语音；失败时插件把原因返回给模型，由模型决定接下来怎么回。

例如：模型用文字解释完一件事，再补一句语音「早点休息」；
技术长文、代码和需要复制回看的信息，模型会优先留在文字里。

## 安装与首次验证

1. 把本目录放进 AstrBot 的 `data/plugins/astrbot_plugin_tts_force/`
2. 在「提供商」页配好一个 TTS 提供商（`text_to_speech` 类型）
3. **关掉 AstrBot 自带的 TTS**（`provider_tts_settings.enable = false`），否则同一条回复会被念两遍
4. 重启 AstrBot。插件配置里「语音提供商」留空＝跟随当前会话，也可以指定一个
5. 私聊机器人发 `/语音测试`：它绕开模型直接合成一句固定话，用来确认**语音服务和发送链路**通了

还需要模型这一环：用**支持工具调用的模型**，并确认 `send_voice` 已启用、对当前会话可用
（工具在插件管理页可以单独停用）。`/语音测试` 通了只说明语音服务正常，
正常聊天里能不能念，取决于模型是否真的调用了工具。私聊和群聊都能由模型调用。

## 使用示例

```
用户：今天好累啊
模型（文字）：辛苦了，早点躺下。
模型（调用 send_voice）：早点休息，明天再说。
```

用户说的是「念给我听」「用语音说」「语音回我」时，模型会优先满足；但它仍会自己判断场合——
问「‘念给我听’这个功能怎么用」属于功能咨询，用文字解释更合适。

## 四项配置

| 键 | 默认 | 说明 |
|---|---|---|
| `provider_id` | 空 | 留空＝跟随当前会话；选了就只用它，它失效时直接报配置错误，不会改用其他服务发送 |
| `max_chars` | `30` | 单次字数上限，允许 10–300。超过就拒绝并回给模型实际长度，句子不会被截断 |
| `timeout` | `120` | 单次合成等待上限，允许 5–600 秒 |
| `test_text` | 「语音测试成功…」 | `/语音测试` 念的那句话，最多 200 字 |

`max_chars` 和 `timeout` 都是直接填数字的输入框，没有滑块；填了允许范围之外的值会按边界取。

**超时要留余量**：AstrBot 的工具调用自己也有超时预算（`agent_runner.config.misc.tool_call_timeout`，
默认 120 秒）。两边一样大时，谁先返回并不确定——工具可能先被宿主取消，你就看不到插件报的超时原因。
想让插件必定先给出「合成超时」这个结论，把 `timeout` 设得比宿主预算小十几秒（例如 100），
或者把宿主预算调大。

**字数为什么默认 30**：自建 qwen3-tts 实测约 0.5 秒/字，30 字≈15 秒合成。

## 工具返回什么

| 情况 | 返回给模型 | 用户收到 |
|---|---|---|
| 成功 | 「语音已经发出去了，不要把同一句再用文字重复」 | 一条语音消息 |
| 超过字数上限 | 「这段话 63 字，超过单次语音上限 30 字，没有发送…」 | 什么都没有（句子不会被截断） |
| 上一条还在合成 | 「还在合成，这条没有发出」 | 什么都没有 |
| 提供商/网络/鉴权问题 | 失败分类 + 脱敏后的原因 | 什么都没有 |
| 音频文件不可用 | 「合成结果不可用：音频数据被截断」 | 什么都没有 |
| 指定的提供商不存在 | 「配置的语音提供商 X 不存在，请到设置里重新选择」 | 什么都没有 |
| 发送失败 | 「语音没有发出去：原因」 | 什么都没有 |
| 发送超时 | 「发送结果**未确认**，可能已经发出去了，不要立即重试」 | 可能收到了，可能没有 |

失败也会变成一句普通的工具结果，不会把异常抛给模型框架（宿主取消这次工具调用除外）。
除「结果未确认」会明确要求不要重试外，其余失败都只给原因，后续怎么回由模型自己决定。

## 常见问题与自检

**一条语音都没收到？按顺序排除：**

1. `/语音测试` 发语音失败 → 语音服务本身的问题，看报错分类：鉴权失败、连不上接口地址、
   模型或音色无效、合成超时、音频文件不可用
2. `/语音测试` 正常但聊天里不念 → 语音服务和发送链路都没问题，接着查：插件和 `send_voice`
   工具是否启用、模型是否支持工具调用、这一轮模型有没有真的发起调用（日志里搜 `语音已发送`）
3. 念了两遍 → AstrBot 自带的 TTS 还开着，关掉它

`/语音测试` 私聊谁都能用，群里只给管理员。

## 从 2.x 升级

3.x 移除了**概率触发**和**回复标记转换**这两套自动机制：以前靠掷骰子或正则判断要不要念，
现在只有模型真的调用工具才会念——模型仍然可以主动调用，只是判断权在它手里。
同时移除的还有关键词识别、场景正则、长期偏好记忆和自动改写回复。

配置项只保留 `provider_id`、`max_chars`、`timeout`、`test_text` 四项。
插件不再有自己的总开关（在插件管理页停用插件，宿主会一并停用它的工具），
也不再手写旧配置清理（宿主加载配置时会删掉 schema 之外的键）。

## 开发与测试

```powershell
python -m pytest tests -q
```

83 条，用假事件和假 provider，不需要连 QQ 或真的 TTS 服务。但**需要能导入 AstrBot 本体**
（插件通过 `astrbot.api` 注册工具）：用 AstrBot 自己的虚拟环境运行，或把 `ASTRBOT_ROOT`
指向 AstrBot 主程序目录。缺依赖时 conftest 会直接报出这条原因，不会静默跳过。
